A YAAT room picker in vTBFM's Traffic source panel

Three ways to put the YAAT room list into Admin › Traffic source, drawn with vTBFM's own theme tokens, Geist type and button, input and panel classes from origin/api. Every lane shows the same moment: the beta runs live VATSIM, the admin has chosen YAAT room, and the list holds four rooms, one with no scenario yet.

The lanes work: pick, type, Refresh and Switch behave as described, and confirming a switch plays the restart and lands on the Sign in again state the maintainers expect after every switch. Grey text is annotation; everything inside a frame is vTBFM.

Set by the maintainers, the same in every lane

Typed room ID stays beside the list, for a room the list lacks and for the no-token case.

Fetch on open plus Refresh, no polling; the server caches 20–30 s per session.

No scenario yet rooms are listed, labelled, and selectable; the confirmation repeats the note.

Live VATSIM stays as the way back.

After every switch the user is still signed in but has no token: the picker reads Sign in again to list YAAT rooms, as information, with Room ID still there.

Sandbox sign-in against a production yaat-server says plainly that the list needs a production VATSIM sign-in.

Each room shows room ID, ARTCC, creator initials, scenario or none, members†, aircraft†, paused or running†.

† Not in yaat-server's /feed/rooms entry today, which sends roomId, artccId, creatorInitials, scenarioName, hasScenario and feedUrl (VatsimRoomListEndpoints.cs). Drawing these three needs new fields on the YAAT side.

The open choice: how the list reads and how a room is applied

Three lanes, same state
A

Native dropdown

How: pick a room in a <select> grouped by ARTCC; it writes the ID into Room ID, and the existing Switch and confirmation apply it. Worst case: each room is one line of plain text, so paused/running and No scenario yet are words, not marks, and the popup's width and font are the OS's.

A, opened

B

Row list, select then Switch

How: one row per room on two lines; clicking a row selects it and fills Room ID, and the existing Switch applies it after the confirmation. Worst case: editing Room ID after picking clears the row, so for a moment the list shows nothing picked; past six rooms the list scrolls inside the panel.

C

Row list, Switch on each row

How: each row has its own Switch, which opens the restart confirmation for that room at once; Room ID keeps its own Switch below. Worst case: five Switch buttons in one panel, so a stray click is one dialog from restarting the beta for everyone, and the radio-then-Switch flow above becomes a second way to do the same thing.
